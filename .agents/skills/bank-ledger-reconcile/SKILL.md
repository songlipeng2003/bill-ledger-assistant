# 银行与账本对账

只读核对，交付逐笔依据与差异金额。用本次快照，不把历史报告中的待处理状态当作现状。

## 操作

- 明确账单完整周期、持卡人/账户、交易类型、时区及对账范围。“9月账单”不自动等于9月自然月。
- 优先读取授权的账本接口；只能操作浏览器时，使用当前环境已提供的浏览器工具。随手记筛选及分页易异步变化，按[读取核验](references/browser-readback.md)确认实际数据覆盖。
- 数据标准化与脚本使用见[输入合同](references/input-contract.md)。脚本不联网、不读真实账户、不修改账本，只比较提供的JSON快照。
- 在项目根目录可执行：
  ```sh
  python .agents/skills/bank-ledger-reconcile/scripts/reconcile.py INPUT.json --out REPORT.json --markdown REPORT.md
  ```
  从其他目录使用当前实际 skill 路径，不能依赖用户机器的固定绝对路径。

## 匹配与结论

1. 同账户、同币种、精确金额、正确方向/类型；日期窗口来自已确认配置。默认零天，不把汇丰窗口推广到别的银行。
2. 一对一分配实际账目。同额独立事件保留数量；重复来源先在提取阶段有证据地关联同一事件。
3. 还款匹配转入该信用卡的转账，不当成消费；自有账户转账不重复记收入/支出。渠道与真实付款账户分开说明。
4. 商户缺失、多个可能对应、账户不同、日期超窗口等保持待确认，不因为近似匹配而自动放行清理。
5. 原始金额、用途或最终入账不确定时列信息不足。汇总只列可量化的未匹配流水，不能把不确定项算成确定损失。
6. 分卡、分币种汇总。支出差、退款/收入差、还款/转账差分别列；不相加不同币种，也不将旧账单应还当作当前欠款。
7. 脚本结果是辅助证据，不能替代未读完的邮件/附件、未覆盖的账本页或未经确认的账户映射。

## 输出

范围与覆盖 → 逐笔匹配/差异 → 按账户币种汇总 → 还款与转账 → 信息不足项 → 邮件级保留/候选依据。没有期初余额及完整期间变动时，不输出精确余额差。

清理候选不表示已获删除授权；补录计划也不表示已获写入授权。
